# HALO File Bridge composition

Read the connected folder's complete AGENT_GUIDE.md and live project-state.json. Follow that guide as workflow authority. Repository reference: [current protocol and package map](../../docs/file-bridge-protocol.md). Repository development follows [AGENTS.md](../../AGENTS.md).

Use strict halo-score only. Verify connected ROOT before writes; bind STATE/ID/REQUEST/RECEIPT once. Never substitute the workspace, create directories or switch roots after access failure. Revision comes only from STATE. Choose explicit compatible timbres and compose original notes, accompaniment, development and rests across all requested bars. Slots, roles, banks and timbres are distinct.

Order: ROOT_VERIFIED -> REVISION_READ -> ID_FIXED -> SCORE_READY -> REQUEST_WRITTEN -> RECEIPT_CHECKED -> RESULT. Complete/read back ID--role.json companions before requests/ID.json. Receipt is only responses/ID.result.json under the same root/ID. Matching applied/rejected are terminal. Review scoreReport and end on pending_approval with an invitation to approve. Corrections keep ID/paths, maximum two rounds, changed submissionVersion. Absent/stale receipt: built-in wait only, at most three reads 4-5 seconds apart; without wait tool one immediate reread then unconfirmed. No shell waits, delegated waiting or indefinite approval polling.

For connected-folder composition use file tools only: no browsers, servers, ports or executables to invoke HALO. These restrictions do not apply to repository development or explicitly requested browser regression. WebMCP/internal operations are separate APIs, never File Bridge requests.

### Musical evidence and task boundaries

The current connected guide contains no ready-made scores to copy. Before publishing, derive actual events per voice for every bar, compare them with the planned entrances/development/rests/ending, and compute real seconds. Verify requested key root/mode and actual MIDI; changing key alone does not transpose authored notes. Compare saved data with scoreAudit and all PART_BAR_GAP warnings; never invent a climax or excuse accidental gaps with a continuous shaker. Intentional rests and sustained tails remain valid.

EVERY later user message changing music starts a NEW ID with live STATE revision. Same-ID repair is only for the current unfinished submission in the current turn. Once pending_approval has been reported, or applied/rejected reached, retire the ID for agent writes. Receipt statuses and approved are outputs, never objects to publish as requests. Human approval happens only in HALO. A prior pending proposal must be applied/rejected there before the next queued proposal is reviewed. HALO cannot enforce another agent file tool's read/write budgets; see docs/file-bridge-tool-adapter.md for the external integration requirements.

## Local packaging

`drums.js`, `bass.js`, `guitars.js` and `keys.js` contain only generated registration calls with embedded PCM WAV base64. This deliberate format preserves classic-script **direct file opening** as well as HTTP and GitHub Pages under a repository subpath; it avoids blocked `file://` fetches, a backend, an encoder dependency and any runtime third-party URL. Binary WAV contents are checked against the manifest in Node tests. Together the four packs are about **65.47 MiB** (49.10 MiB decoded WAV bytes). They load only when REACTOR is selected/played or exported; AMBIENT requires none of them. Playback begins after loading and decoding all packs; failure is explicit and retryable, with no procedural substitute.

Developer conversion: mono 32 kHz, 16-bit PCM; 20 Hz highpass, leading silence trimmed by at most 120 ms, peaks normalized to 0.8 and a 20 ms tail fade. Excerpts are finite (percussion/keys up to 3.5 s; original guitar tails up to 30 s); upstream sustain loops are not used. Nearest recorded note is transposed with Web Audio playbackRate, and alternate strikes are selected deterministically from event velocity/note. Shared buffers are reused within each AudioContext; offline export decodes for its own context. Initial bandwidth/decoding and memory cost depend on the device; the sampler is not a full velocity-layered professional library. Listening and physical Safari/iOS acceptance remain separate from source/hash/render tests.

Rebuild with `python scripts/import-reactor-samples.py` using Python 3, Git, FFmpeg and 7-Zip. These are developer tools only; the deployed site needs no build step or runtime dependencies. The importer writes rights evidence and the planned inventory before importing audio, pins source repositories and generates all packs and hashes. Its download/conversion cache stays in ignored `.sample-work/`.
